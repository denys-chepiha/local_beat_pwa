# Reader, performance and security review — 2026-10-23

## Scope
Changes on feature/reader start from 85cecc2. Reviewed startup, audio/video session restoration, storage writes, bulk operations, import cancellation, local document parsing/rendering, responsive controls, dependency licenses and production CSP. This is a source and automated-browser review, not a penetration test or physical-device certification. No production deployment was performed.

## Findings and changes

| Area | Finding | Change and evidence |
| --- | --- | --- |
| Startup | Video restoration and secondary screens added work before Music could open. | Lazy screens and video hydration; independently restore audio sessions, then select Music. Regression tests include an empty music library with saved audiobook progress. |
| Large playlists | Removing many tracks repeatedly rebuilt queues and saved player state. | Set-based batch removal updates each queue once; 5,000-track regression test. |
| Video storage | Frequent progress events wrote preferences repeatedly; overlapping or failed persistence could diverge from the visible queue. | Coalesced writes, explicit flush points, serialized reconciliation against stored records with per-file commits, retry/recovery tests. |
| Import lifecycle | Deleting a library during an import could recreate records; abandoned duration probes continued decoding; late cover updates could leave orphan data. | Generation guards, abortable probes, transaction-time existence checks and regression tests. |
| Preferences | Unavailable browser preference storage could interrupt navigation or playback. | Guarded access with usable in-memory defaults. |
| Documents | HTML, archive paths, external resources and excessive expansion are untrusted inputs. | Bounded ZIP validation, CRC/expansion checks, strict markup sanitization, owned raster URLs, pixel limits and opaque-origin frame isolation; hostile-input tests. |
| PDF | Rendering every page and retaining large canvases would exhaust tablet memory. | Nearby-page rendering, bounded canvases/page counts, cleanup/cancellation, local workers/resources and lazy loading. PDF scripting and XFA are not enabled. |
| Reader position | Concurrent writes could save an older location; transient layout and repeated pagination rounding could move a reflowed book to the wrong place. | Serialized progress writer, coalescing, close/background flush, bookmark mutation lock, readiness-gated controls and a logical position retained across automatic reflow. |
| Continuous reading | The iframe root could scroll while the position listener watched its body. | Use an explicit scroll container; WebKit also required a trusted isolated bridge because its scriptless sandbox suppresses parent event callbacks. ADR-0005 records the boundary and browser evidence. |
| Offline reading | The opaque frame could not retrieve an external bridge from the parent's service-worker cache. | Embed exact static source authorized by a parent CSP hash and child nonce. Build/hash checks and offline browser probes preserve isolation; ADR-0006 records delivery. |
| Controls | Audio and video ranges used different styling and behavior. | One accessible native ProgressSlider for media seeking/volume, reading progress and text size. Pointer, keyboard, normalization and video-preview regressions. |
| Test environment | Node's experimental Web Storage shadowed jsdom and caused 13 baseline failures. | Disable that Node experimental global in the test process; retain all assertions and checks. |

The new library stores metadata, original files and covers separately. Import/removal is transactional; additive schema version 4 preserves existing media. See docs/architecture/reader.md and ADR-0003 for boundaries and supported-format limitations. Existing persistent video behavior came from the base commit and is recorded in ADR-0004.

## Security and licenses
`pnpm audit` reports zero known advisories across production and development dependencies on the review date. This does not prove the absence of unknown defects.

Approved reader dependencies: PDF.js (Apache-2.0), fflate (MIT), DOMPurify (Apache-2.0 or MPL-2.0), marked (MIT), mammoth (BSD-2-Clause). PDF asset emission includes required local CMaps, Foxit fonts and decoder fallbacks with licenses; unused Liberation fonts, scripting and WASM resources are not shipped. Imported document scripts, remote images, styles, fonts, SVG and forms are omitted. DOCX external file access is disabled.

The production CSP permits neither unsafe-eval nor unrestricted inline scripts. It authorizes the exact trusted reading bridge by hash; the isolated frame also requires a nonce. Local PDF workers/fonts and opaque-origin document frames have explicit allowances. Final browser checks used a local static server with the actual configured response headers; live headers remain a release check. Imported fixtures produced no external network requests and no page exceptions.

# Mobile video controls — 2026-10-23

The phone player now separates the picture from its controls. A single row below
the timeline contains play/pause, playlist, settings and fullscreen. Previous/next
and skip buttons remain on desktop; phones retain timeline and double-tap seeking.
Speed, repeat and mute/volume are available in an expandable settings panel.

The playlist opens below the controls on phones, with bounded scrolling and
wrapping filenames. Opening either panel closes the other. Selecting an entry,
including the active entry, closes the playlist. Escape dismisses a panel and
returns keyboard focus to its toggle.

Inline phone controls remain visible. Fullscreen controls hide while playing and
release their space to the picture; a tap restores them. Full-window fallback
keeps the app playlist available when container fullscreen is unavailable on iOS.
