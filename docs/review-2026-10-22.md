# Project review — 2026-10-22

## Scope and evidence
Reviewed the client playback engine, queue/list interactions, IndexedDB lifecycle, file/metadata handling, UI subscriptions, responsive styles, PWA configuration, dependencies and deployment headers. This is a code and automated-browser review, not a penetration test or physical iPad certification. No field Core Web Vitals data was available.

## Video behavior
See ADR-0002-video-session-playlist.md for the accepted session storage and fullscreen decision. The queue retains File references across navigation and releases them when removed or the app closes/reloads. Only the active video has an object URL; it is revoked on replacement/unmount. There is no media upload, transcoding, new video dependency or IndexedDB schema change.

Transport: play/pause, previous/next, automatic advance, repeat off/all/one, seek, ±10 seconds, speed, mute and volume where supported. Container fullscreen retains playlist and controls; a full-window fallback preserves them when the platform rejects fullscreen. Controls hide after 2.5 seconds and reveal without pausing on the first touch. Tests cover both the touch gesture sequence and session navigation.

## Verification
- Baseline: 82 tests and production build passed.
- Final automated suite/build: see docs/CURRENT_STATE.md for counts and commands.
- Chromium: local WAV import/playback, seek followed by next-track reset, pointer reorder, tablet full audio player, MP4 playback, fullscreen, control hiding/reveal and exit. No page errors in these scenarios.
- Chromium responsive checks: 390×844, 820×1180, 1180×820 and 1440×900; no horizontal document overflow in the tested Video views.
- Production preview: service worker became active; offline reload and local MP4 playback passed. Configured CSP/security headers were applied by the browser harness to verify compatibility; deployed response headers remain a release check.
- WebKit: video playback, fullscreen/fallback, automatic control hiding and navigation passed with no page errors.
- WebKit audio persistence: blocked by the installed test runtime. A separate native IndexedDB probe, without application code, saved text but rejected both an in-memory Blob and File with `UnknownError: Error preparing Blob/File data to be stored in object store`. This does not establish whether a physical Safari device has the same issue.
- Design detector flagged two existing width transitions; removed them. Finish review found a touch-reveal pause issue; fixed and verified by a focused regression test.
- `git diff --check` clean.

## Physical-device release checks
Still required on the intended iPad/iPadOS and Mac Safari versions:
1. Installed PWA: portrait/landscape, Split View, safe areas, keyboard and hardware volume.
2. Add music/audiobooks, reload, resume, lock screen, unlock, and change tracks using system controls.
3. Select videos from Files and an actual attached drive; disconnect/reconnect and verify recovery.
4. Fullscreen, first-tap reveal, seek, next/previous, repeat, exit and foreground/background transitions.
5. Real video codecs and large files; support depends on browser/device. No universal MKV/AVI/codec claim is made.
6. Verify live response headers and a fresh service-worker update after the approved release.

Original files remain the recovery source if the browser evicts local storage. No deployment, commit, push, merge or real-library deletion was performed by this review.
